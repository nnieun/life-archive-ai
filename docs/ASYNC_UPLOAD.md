# 백그라운드 업로드와 인덱싱

업로드 페이지는 파일을 서버에 전송한 뒤 작업 ID를 받는다. 기억 추출과 인덱싱은
FastAPI 백그라운드 작업에서 실행하므로, 접수 후 다른 페이지로 이동해도 계속 처리된다.
모든 페이지의 공유 앱 영역에서 1초마다 상태를 조회한다.

업로드 진행 단계와 경과 시간은 업로드 페이지에서만, 대화 진행 단계와 경과 시간은 대화 페이지에서만 표시한다. 다른 페이지에서도 백그라운드 상태 조회와 완료 알림은 유지한다.
처리가 끝나면 페이지와 관계없이 하단에 완료 알림이 10초간 표시된다.
업로드 페이지로 돌아오면 기억·구간·빈칸·인덱싱 결과를 다시 확인할 수 있다.

## API

- `POST /api/v1/memories/ingest/jobs`: 기존 업로드 필드에 `session_id` 추가. 접수 시 202와 작업 ID 반환.
- `GET /api/v1/memories/ingest/jobs/{job_id}?session_id=...`: 상태·진행 단계·완료 결과 조회.
- 상태: `queued`, `running`, `completed`, `failed`, `cancelled`.
- 세션이 다르거나 작업이 없으면 404. 같은 세션·파일 이름·내용의 진행 작업은 409.
- 잘못된 파일 이름·Base64·빈 내용·TXT 인코딩은 접수 전에 422.
- 등록 완료된 파일과의 충돌 등 처리 중 실패는 작업의 `failure_code`, `error`로 전달한다.
- 기존 동기 `POST /api/v1/memories/ingest` API는 호환성을 위해 유지한다.

작업 상태는 SQLite `ingestion_jobs`에 저장한다. 파일 본문·Base64·API 키·예외 메시지·
로컬 경로를 작업 기록에 복사하지 않는다. 같은 작업은 한 번만 완료 결과로 반영한다.
개인정보 삭제로 해당 원본이 삭제되면 관련 작업 결과와 진행 정보도 비우고 작업을 취소한다.

## 범위와 재시작

페이지 이동은 작업을 취소하지 않는다. 파일 전송이 끝나고 작업이 접수되기 전에는
전송 자체가 끝나야 하므로 접수 여부를 먼저 확인한다.
브라우저를 닫아도 서버 작업은 계속되지만 새 브라우저 세션에서 기존 작업 알림을
복원하는 기능은 포함하지 않는다. 생성된 기억은 SQLite에 저장되어 기억 페이지에서 확인할 수 있다.

백그라운드 실행은 백엔드 프로세스 안에서 수행한다. 서버 종료·재시작 시 작업을
자동 재개하지 않으며, 다음 시작 시 남은 진행 작업을 `server_restarted` 실패로 표시한다.
강제 종료가 있었다면 이미 생성된 기억이나 등록 상태를 확인하고 재시도한다.
원본 보존·실패 정리·기억 추출·인덱싱의 기존 업무 로직은 유지한다.

코드 변경 후 백엔드와 Streamlit을 재시작한다.
