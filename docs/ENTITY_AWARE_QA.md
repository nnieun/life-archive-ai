# 엔티티 기반 검색과 완전성 검증

LangGraph 상태의 `query_plan`(mode, matched_people, subqueries, required_memory_ids)을 retrieve → generate → verify 전체가 공유한다.

- **인물 개요**: 질문에 알려진 인물명이 있으면 SQLite `people`으로 그 인물의 모든 기억을 필수 근거로 지정한다.
- **복합 질문**: 질문을 하위 질문으로 나눠 각각 검색하고, 하위 결과 1건씩을 필수 근거로 합친다.
- **완전성 검증**: 필수 기억 ID 중 답변이 인용하지 않은 것이 있으면 코드가 `incomplete_answer`로 차단한다. 검증 모델이 반환한 누락 ID도 필수 목록 안에 있는지 확인한다.

## 평가 (합성 기억 7건, gemma4:e2b + bge-m3, top_k=3, 3회 반복, 캐시 끔)

실행: `PYTHONPATH=. uv run python scripts/evaluate_entity_aware_qa.py --repeats 3`
결과: `data/processed/entity_aware_qa/20261005T114206Z_4f6b5e/`

| 항목 | baseline | entity_aware |
|---|---|---|
| 1. "영수 오빠는 누구야?"에 라디오·김치볶음밥 모두 인용 | 3/3 | 3/3 |
| 2. 특정 사건 질문에 불필요한 기억 인용 | 0건 | 0건 |
| 3. 복합 질문 검색 재현율 / 통과 | 0.75 / 0/3 | 1.0 / 3/3 |
| 4. 근거 없는 질문 거절 | 3/3 | 3/3 |
| 전체 통과 | 9/12 | 12/12 |

5. 응답 시간(중앙값): 개요 12.4→12.2초, 특정 사건 10.5→10.6초, 근거 없음 4.8→5.6초, **복합 5.8→26.0초**. 복합 질문은 하위 검색과 더 긴 답변 때문에 크게 늘어난다. 단, baseline의 5.8초는 근거 부족으로 거절한 시간이라 같은 일을 비교한 수치가 아니다.

6. 완전성 검사가 차단한 실패: **이번 평가에서는 `incomplete_answer` 차단이 0건**이었다. 모델이 필수 기억을 빠뜨린 경우가 없었고, 이 검사가 실제로 막은 사례는 아직 측정되지 않았다. 코드 경로는 단위 테스트로만 확인했다.

## 한계

- 항목 1은 baseline도 통과했다. 이 합성 세트에서는 top_k=3 안에 두 기억이 우연히 들어와 개선이 입증되지 않는다. 기억 수를 늘리거나 top_k=2로 낮춘 추가 평가가 필요하다.
- 이번 작업 중 평가에서 "담임 선생님"을 인용한 문장이 "선생님"이라고 쓰면 `unsupported_person`으로 오거절되는 오탐을 발견해, 인용된 더 긴 이름에 포함된 이름은 건너뛰도록 고쳤다.
- 합성 데이터 7건·반복 3회라 통계적 결론은 아니다. 운영 데이터는 사용하지 않았다.
