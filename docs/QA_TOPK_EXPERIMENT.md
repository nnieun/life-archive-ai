# 검색 개수와 답변 신뢰성 비교

## 문제와 가설

운영에서 생성·검증 시간이 검색보다 길었다. 모델에 전달하는 기억을 5개에서
3개로 줄이면 입력 처리 비용이 줄 수 있지만, 여러 사건을 종합하는 질문은 근거를
잃을 수 있다. 따라서 속도만으로 기본값을 바꾸지 않고 완전성과 거절 여부를 함께 평가한다.

## 재현 방법

```powershell
.\.venv-review\Scripts\python.exe scripts\evaluate_qa_topk.py --repeats 2
```

Ollama의 Gemma와 BGE-M3를 사용한다. 외부 LLM·임베딩 API를 호출하지 않는다.
운영 SQLite·Chroma·대화는 열지 않고 합성 기억 13개로 독립 DB와 인덱스를 만든다.
원문 생성과 기억 추출은 평가 범위가 아니다. 합성 사건을 정답 기억으로 직접 등록한다.
같은 질문을 top-k 5/3으로 각각 실행하며 질문·반복별 실행 순서를 뒤집는다.
실제 BGE-M3+BM25 하이브리드 검색과 기존 생성·검증 그래프를 사용한다.
검증은 유지하고 캐시와 재시도는 끈다. 모델·프롬프트 정책은 양쪽에 동일하다.
초기 인덱싱과 워밍업은 제외하며, 요청 시간과 모델 입력 문자·토큰 처리 시간을 기록한다.

질문은 단일 사건 2개, 여러 사건 2개, 불확실한 날짜 1개, 근거 없는 생일 1개다.
네 사건을 요구하는 질문은 top-k 3의 용량 한계를 확인하는 의도적인 경계 사례다.
이는 실제 사용자 질문 분포나 전체 한국어 검색 성능을 대표하지 않는다.

## 평가 기준

- 정답 기억 검색 비율: 필요한 기억 중 검색된 비율.
- 인용 완전성·정밀도: 정답 기억의 누락 및 불필요한 인용 여부.
- 필수 사실 포함: 사전에 정의한 표현 후보가 답변에 있는지.
- 올바른 거절: 근거 없는 질문을 `insufficient_evidence`로 거절했는지.
- 완전 답변 통과: 검증 통과 + 필요한 인용·필수 사실을 모두 포함했는지.

모델 자체 검증 통과는 답변 완전성을 보장하지 않는다. 부분 답변은 별도 실패로 센다.
필수 표현 검사는 제한적인 자동 검사이며, 의미가 같은 다른 표현을 오판할 수 있다.
합성 답변을 수동으로 검토하고 자동 점수와 함께 해석한다. 정밀도를 환각률로 부르지 않는다.
샘플과 반복 수가 작아 통계적 우위나 운영 응답 시간 보장을 주장하지 않는다.

출력은 `data/processed/qa_topk/실행ID/`의 manifest, results.jsonl, summary.json,
독립 SQLite·Chroma다.

## 결과

실행 결과는 `data/processed/qa_topk/20261005T110728Z_e12997/`에 저장했다.
질문 6개를 각 설정으로 2회씩 실행하여 설정별 12회, 총 24회를 측정했다.

| 질문 유형 | top-k | 중앙 시간 | 완전 답변 통과 | 평균 검색 재현율 |
|---|---:|---:|---:|---:|
| 단일 사건 | 5 | 13.162초 | 4/4 | 1.000 |
| 단일 사건 | 3 | 11.982초 | 4/4 | 1.000 |
| 여러 사건 | 5 | 19.240초 | 1/4 | 0.875 |
| 여러 사건 | 3 | 15.796초 | 2/4 | 0.875 |
| 불확실한 날짜 | 5 | 10.817초 | 2/2 | 1.000 |
| 불확실한 날짜 | 3 | 9.383초 | 2/2 | 1.000 |
| 근거 없는 생일 | 5 | 10.399초 | 0/2 | 해당 없음 |
| 근거 없는 생일 | 3 | 4.986초 | 2/2 | 해당 없음 |

전체 중앙 시간은 top-k 5가 13.162초, top-k 3이 11.982초였다. 생성 모델에
전달한 답변 단계 입력은 평균 3,137자에서 2,744자로 12.5% 줄었다. 완전 답변
통과는 top-k 5가 7/12, top-k 3이 10/12였다.

여러 사건 네 개를 요구한 질문은 두 설정 모두 필요한 첫 출근 기억을 검색하지 못해
실패했다. top-k 5는 세 사건 질문에서 근거를 모두 검색하고 인용했지만 필수 사실 하나를
답변에서 누락한 실행도 있었다. 두 경우 모두 모델 검증은 통과했으므로, 현재 검증기는
각 문장의 근거는 확인하지만 질문 요구사항의 완전성까지 보장하지 못한다.

근거 없는 생년월일 질문에서 top-k 5는 라디오 수리 시기 기억을 생년 정보처럼 답해
두 번 모두 실패했다. top-k 3은 두 번 모두 `insufficient_evidence`로 거절했다. 이 결과는
top-k 3이 일반적으로 환각을 방지한다는 증거가 아니라, 더 많은 유사 기억이 질문과 다른
사실을 답하게 만들 수 있다는 실패 사례다.

## 결정

현재 기억 대화는 단일 사건 질문이 주 용도이고, 이 작은 합성 평가에서는 top-k 3이
정확도를 유지하며 더 빨랐다. 대화 API와 프론트엔드의 기본값을 3으로 변경한다.
사용자가 명시한 top-k는 그대로 존중하며 자서전의 기본값 10은 변경하지 않는다.

여러 사건을 종합하는 질문에는 top-k를 무조건 5로 늘리지 않는다. 후속 과제로 질문을
하위 사건으로 나누어 각각 검색한 뒤 합치는 방식과, 답변 검증에 질문 요구사항 완전성
검사를 추가하는 방식을 별도 평가한다. 이번 표본은 작으므로 운영 데이터의 익명화된
평가 세트를 확보하면 같은 절차로 다시 판단한다.
