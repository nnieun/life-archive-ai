# 페이지 이동 중 질문 처리

대화 화면은 `POST /api/v1/chat/jobs`로 질문을 제출하고 작업 ID를 받습니다.
FastAPI 백그라운드 작업이 기존 QA 그래프를 실행하며, 상태와 완료 결과는
SQLite `chat_jobs`에 저장됩니다. 작업 제출 과정에서는 모델을 호출하지 않습니다.

`GET /api/v1/chat/jobs/{job_id}?session_id=...`로 상태를 조회합니다.
상태는 queued, running, completed, failed, cancelled입니다. 기존 동기
`POST /api/v1/chat`도 유지합니다. completed는 처리가 끝났다는 의미이고,
근거 부족/검증 거절 여부는 결과의 validation_result에서 확인합니다.

Streamlit 공통 화면의 fragment가 1초마다 작업을 조회합니다. 페이지를 이동해도
조회가 계속되고, 완료하면 오른쪽 하단에 “답변이 완료되었습니다.”를 10초간
표시합니다. 대화 페이지로 돌아오면 완료 답변과 인용을 확인할 수 있습니다.
대기 중인 질문이 있으면 같은 대화에서 새 질문을 제출할 수 없습니다.
API에서도 세션별 대기 작업을 한 개로 제한합니다.

브라우저가 닫히거나 새 세션이 생기면 공통 화면 알림은 표시되지 않습니다.
OS 알림 기능은 아닙니다. 서버가 재시작되면 진행 작업은 실패로 표시됩니다.
MVP는 단일 백엔드 프로세스로 실행합니다. 별도 작업 큐나 프로세스 재시작 후
자동 재개는 지원하지 않습니다.

기록 삭제 시 진행 작업은 cancelled로 바꾸고, 해당 기억을 참조하는 완료
결과는 제거합니다. 취소 상태의 작업에 실행 중인 worker가 결과를 덮어쓸 수
없습니다. 이미 진행 중인 모델 연산 자체를 강제로 종료하지는 않습니다.
대화 세션 삭제 시 그 세션의 작업 결과도 제거합니다.

백엔드와 프론트엔드를 재시작하고 질문 제출 → 다른 페이지 이동 → 하단 알림
확인 → 대화 페이지 복귀 순서로 사용하세요.
